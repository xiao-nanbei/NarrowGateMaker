## 改 live，保留模型

用户选择迁移 live 输入，不重新训练或改写冻结模型。显式的 `ml.feature_protocol: execution_v1` 路径订阅 BTCUSDC 原生 `@trade` 逐笔消息，通过 [LiveExecutionFeatures](../../live/feature_protocol.py) 将成交与局部盘口快照交给现有[共享特征计算器](../../data/observation.py)。既有版本保留独立旧路径；模型与协议不匹配、跨协议热重载均拒绝。本次源码实现不等于已激活的新版本。

[Live 信号消费者](../../strategy/live_public_signal.py) 校验全部13个未修改的 head 文件、元数据、特征列、训练身份及方差单位。上线要求单独的哈希绑定输入授权，不改写冻结元数据；仅在内存中映射传输身份。实时输入保留实际交易所发布、接收、就绪时钟及自身身份，不称为 Tardis 事实或套用历史仿真延迟。适配器采用100毫秒迟到容限、1秒盘口最大年龄；部署须将这些设置与模型、P3及配置绑定。

## 来源粒度和安全边界

覆盖九个成交 ID 的聚合包仍只有一个观测事件，不能替代逐笔来源的 `observed_trade_count_10s` 或 `trade_intensity_burst_guard`；兼容检查继续拒绝这种路径。有界、只读的交易所探测实际收到 BTCUSDC 原生 `trade` 消息及独立 `t` 身份。实现消费这些消息，不伪造聚合包子事件。端点可用不能独自证明持续完整性、目标主机时序或部署就绪。

重复身份不增加成交量，冲突或倒退身份会拒绝。断线或检测到 ID 缺口后清除滚动特征和兼容价格历史。预热要求完整60秒已观测窗口与新鲜盘口。缺失深度保持未知，陈旧盘口不能提供新鲜价格，禁用 REST 聚合成交预填。新协议输入支持失效时撤销已有报价，并阻止直接重新报价。已停止的研究和冻结模型字节均不改变。

## 验证范围和上线边界

[适配器测试](../../tests/test_live_feature_protocol.py) 覆盖粒度、身份、因果时钟、无效消息、缺口、断线、盘口陈旧性及历史／共享特征一致性。[消费者测试](../../tests/test_live_public_signal.py) 使用合成模型核验所有 head 与离线消费者的预测一致性、产物哈希不变、授权拒绝、订阅／分发隔离、预热及撤单保护。既有 live、行情和模型回归测试继续纳入验收。

当前私有 live 配置、运行指针和远端服务尚未切换。实流探测还发现交易所发布时间领先本地接收时间，时钟对齐因此是明确的待验收问题，不意味着可以截断时间戳或重训。候选仍须完成精确的私有模型／P3／配置授权、完整报价动作及目标运行环境延迟验收，再走既有[部署事务](aws_ec2_live.zh-CN.md)，包括新的账户对账和健康验收。本地测试不是部署或盈利证明。
