## 最小保留集合

保留能解释问题、定位实际运行、重算已报告会计与比较、支撑结论限制的最小证据集合。“理论上可以重跑”不能成为删除唯一结果、模型字节或原始输入的理由。只有摘要哈希、没有可读取对象，不算依赖已保留。体积、年龄、`COMPLETE` 状态或文件名都不是删除证据。

| 类别 | 必须保留的证据，可存本归档或通过已验证的规范位置引用 |
| --- | --- |
| 实验合同 | 原问题、精确基线/候选、账户日历及初始化、拆分/历史使用、随机种子、停止决定、指标/统计、包含获准变更的完整生效配置 |
| 来源身份 | 实际源码快照或可恢复提交及 dirty/private overlay；运行时/依赖/native 身份；输入/模型/校准/恢复绑定。训练还保留支持量、权重、选择/refit 配置、模型成品和验收 |
| 正式结果 | 原身份的逐账户正式结果、会计、每日账本/权益增量、费用/资金费/终点 MTM、原合同要求的成交及风险/作用诊断；配对比较、覆盖和缺失；解释排除原因所需的部分/失败证据 |
| 验收证据 | formal/durable 身份和完成核查、原任务/Attempt 与退出回执、真实恢复/一致性测试、唯一故障诊断及修复证据；不能只有截图或调度计数 |
| 结论与限制 | 有单位/分母的可读结论、计划与实际覆盖、亏损/不确定性、历史使用/模型/模拟器限制、晋升或不晋升决定、收尾回执 |

不存在“只留 accounting 和汇总就够了”的通用规则。正式结果内嵌成交/诊断时保留原字节；只有另行授权的无损转换完整保留证据、身份映射和读取兼容性后，才能替代。明确 pinned 的一致性验证文件即使形似检查点也保留。存储整理不改写交易结果和历史标签。

一个实验只有一个不可变身份、一个研究归属和一个维护中的 `archive-manifest.json`。已有研究族目录指向清单；已有私有 `experiment-storage.current.json` 只管物理位置，不成为第二套经济状态权威。引用已有绑定清单/回执，不复制全文，也不额外创建逐事件目录记录。

## 共享对象与可删除材料

购买原始数据、facts、已验收 observations、资金费、模型和源码快照由唯一归属保留规范副本及所需备份，不为每个实验复制全套。引用记录位置、原身份、可用性核查和依赖原因。复用 B0 保留原身份。依赖未知会阻止最小归档认证，不自动触发复制、重建或删除。

可复用 prepare、参考特征和预测缓存进入共享版本化数据存储，不进入永久实验结果目录。遵循[数据工作流](../../.agents/skills/mm-as-glft-ml-spread/references/data-workflow.md)：先复用目标/可信 peer；核实 ORICO 原副本；按账户/版本有限复制到工作盘，最后实际消费者验收退出、无依赖及占用后清理。用户2026-10-19明确取消 prepare 缓存强制网盘备份，不再上传或等待网盘作为清理前置。缓存按精确相对名和每文件字节验收，不重新计算 SHA，不把大小匹配称为密码学一致。正式结果、模型及采购原件仍分别保留必要证据。不开新硬链接/符号链接，不预填全日历，不外盘直接回放。

不因“留个纪念”永久保存重复进度日志、重复调度载荷、过期恢复检查点、传输碎片、临时凭据/工具、编译缓存/中间产物和已完成的一次性启动脚本。先将唯一诊断和必需退出元数据保留到已有归属。按用途过滤运行锁，保留依赖锁文件。若启动脚本含唯一实际参数映射，在别处完整保留并验证前仍是证据。明确要求保留的历史记录是例外，不能一律当垃圾。

## 目录标准

新实验在已有私有归属和保留存储根下使用以下结构，不创建空目录：

```text
<experiment-id>/
  archive-manifest.json       类别、规范引用、完成门与例外
  contract/                   计划、日历、生效配置及身份绑定
  results/<arm>/<account>/    每条原路径的一份规范正式结果
  evidence/                   验收、必要故障/修复及训练证据
  report/                     结论与原比较表
```

共享模型/源码无须在此重复。临时工作、暂存、调度 Attempts 和传输材料留在归档外。已有冻结归档用 `layout=legacy_in_place`：实际路径映射到相同五类，不重命名冻结路径、复制整树、改写结果或移动活动依赖。先统一逻辑入口。

## 收尾门槛与真实状态

完整 `verified_minimal` 认证仍须通过下列全部门槛，但不是每次有限清理已证实可丢弃工作副本的前置条件。局部清理应明确受影响对象、保留替代副本及实际消费者/恢复关系，再经其维护入口核查当前退出、可用性和文件占用。复用仍适用的原验收/来源证据；不因删除一个已完成账户的缓存或检查点而重新验证整个历史日历、重跑经济或重算无关全树哈希。依赖未知时保留受影响对象，并在相关范围阻止最小归档认证，但不阻止其他已独立证明安全的清理。如实记录有限结果，不据此提升整个实验的归档状态。

`economic_status` 与存储状态独立：`active`、`closed_complete`、`closed_partial`、`closed_failed` 或 `unknown`。用户停止的研究可以按部分完成归档；整理存储不恢复缺失覆盖或 fresh holdout。

`archive_status` 从 `inventoried`（已盘点）到 `reviewed_with_exceptions`（有缺口）再到 `verified_minimal`（最小归档验收通过）。最后一种要求五类材料已核查（不适用须有原因）、依赖可定位、无未解决例外，并对每项门槛提供证据：

1. **payload_integrity：**按原合同核查保留正式载荷与身份。保留旧回执，新增本轮核查，不修改历史计数。
2. **dependency_resolution / restore_read_check：**定位源码/模型/输入/结果及所需备份；实际读取或恢复核查，不为归档另跑经济任务。
3. **writers_exited / no_active_or_recovery_consumers / no_open_files：**原写入者已退出，拟删除对象没有活动、排队、恢复、pinned、跨实验消费者或打开文件依赖。未知就保留。
4. **scheduler_residue_review：**经已有维护入口检查该实验的 Attempt 副本、检查点、缓存 blob、暂存/release、一次性工具及临时账号。共享状态和监督元数据不能整树删，不改调度状态强行通过清理。
5. 仅删除已证实可丢弃或冗余的集合；记录精确路径/类别、原因、适用的保留替代对象，逻辑删除字节与实测空闲增量分开。复核保留文件并同步已有存储/缓存/文件索引。允许检查后零删除，不能将未检查写成完成。

校验工具只检查声明、门槛和可选路径存在性，不认证哈希、经济结果、远端可用性、进程退出或删除安全。工具没有删除/迁移命令。格式通过不是证据验收。

```bash
python -m research.governance.experiment_archive inventory <archive-root>
python -m research.governance.experiment_archive init <archive-root> --experiment-id <original-id> --owner <existing-unit> --write
python -m research.governance.experiment_archive validate <archive-root>/archive-manifest.json --check-paths
```

`init` 创建私有 `inventoried` 草案，拒绝覆盖。统计排除清单自身，记录逻辑字节，不计算载荷哈希。必须核查引用和例外。真实路径、详细回执遵循[公开/私有边界](../../docs/public_private_documentation_contract.md)。研究族文档和唯一研究状态索引指向实际结论及归档入口；存在未知完成门时不能宣称全部历史已最小化。

## 回放恢复载荷

本归档合同统一规定检查点及调度残留的保留。每个活动离线任务/臂只保留最新有效、可恢复的检查点及必要元信息；原子发布并验证替代检查点后立即删除上一代，失败或未完成任务的唯一有效恢复点不可删除。不得逐小时累计检查点。完整账户经济、终点及会计验收通过、原进程退出，且无活动、排队、恢复消费者或文件占用后，立即通过原维护入口删除可丢弃的回放检查点及过期侧文件，记录清理量，不等整个实验结束或缓存满14天。保留正式结果、指标、会计和完成回执、模型/输入绑定及明确固定的研究证据。PID退出或调度COMPLETE本身不足以清理。此规则不适用于训练模型检查点或唯一实验结果；不得为修改保留策略而热改冻结经济实现、重启健康任务。
