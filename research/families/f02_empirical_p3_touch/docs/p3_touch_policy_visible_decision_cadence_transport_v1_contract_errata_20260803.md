# P3 Policy-Visible Decision-Cadence Transport v1 Errata

Last materially modified: 2026-08-12

The frozen Spec and machine artifacts are unchanged. This errata narrows their interpretation after an implementation audit.

The current decision BBO uses the same keyed SplitMix64 latency sample as the F06 quote path, and its integer BUY/SELL ticks must match the F06 placement row. The 60-second model context is different: it is generated by applying that sampler independently at 61 synthetic one-second query points. F06 did not persist that complete state history.

Consequently this identity is a deterministic sampled-visibility prediction sensitivity, not exact F06 feature-state parity and not AWS receive-time transport. Its synthetic `feature_ready_ts_ms` also must not be interpreted as an observed per-event receive timestamp.

The correction does not alter the stop decision. The immutable denominator still has only 28 days and three OOF folds, and F05 independently has only one fill in its sparsest side x role x action cell versus the required 30. No value fit, quote mapping, F09 action, Validation read, holdout read, or live authority is permitted.

A future successor must explicitly bind context parameters, replay-compatible duplicate-timestamp handling, every F06 visibility command or equivalent provenance, and a feature-ready clock covering all dependencies. It may claim exact F06 state parity only with persisted state or event-lockstep evidence.
