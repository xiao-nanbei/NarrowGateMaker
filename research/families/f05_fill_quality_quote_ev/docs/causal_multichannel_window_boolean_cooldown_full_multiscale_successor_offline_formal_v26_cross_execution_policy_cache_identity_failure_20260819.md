# F05 Formal-v26 Cross-Execution Policy Cache Identity Failure

Last materially modified: 2026-08-19

Status: `failed_closed_before_sell_cross_execution_policy_cache_key_incompatibility`.

## Scope

Formal-v26 was an execution-only successor to formal-v24. It preserved the frozen 30-day panel, 3,516 opportunities, candidate ladder, folds, exact current-owner B0 policy, repeated sequential-policy estimand, statistics, evidence boundaries, and false action/live permissions. It retained the mmap lifetime repair, excluded every formal-v25 cache, and was intended to inherit exactly 577 completed formal-v24 BUY cache units before restarting only unfinished SELL work.

## Passed Gates

Formal-v26 ran from clean commit `20b60cd8098383b4ebda9d3e0688188987389038` and annotated tag `research/f05/causal-multichannel-window-boolean-cooldown-full-multiscale-successor-offline/formal-semantic-safe-sell-resume-v26-20260818`. It passed direct v24-to-v26 execution invariance, the 577-entry BUY source census, the 3,516-opportunity zero-economic C++ builder walk, first-opportunity eight-arm lockstep, full-day 81-opportunity and 648-arm lockstep, and formal mechanics preflight. The completed-side source walk found 67 outer-train one-shot, 250 inner-OOF, and 260 outer-OOF entries and verified all 67 one-shot semantic-registration contracts without parsing payloads or reading economic outcomes.

## Failure

At nested-run startup, formal-v26 directly inherited and admitted the first ten BUY outer-train one-shot entries. The first BUY inner-OOF repeated-policy request then failed because its formal-v24 predecessor cache key did not exist under the requested candidate policy SHA256. No BUY replay ran, SELL did not start, and no formal result, nested OOF report, scorecard, candidate freeze, promotion conclusion, or intermediate economic value was produced or exposed.

The incompatibility is structural rather than missing storage. A non-B0 candidate's `policy_sha256` is the canonical digest of both its compiled policy and training provenance, including the learning-label request, payload, and receipt SHA256 values. Formal-v26 creates successor-bound learning-label receipts, so an otherwise semantically identical candidate necessarily receives a different `policy_sha256`. Sequential cache keys bind that digest. Replacing only the adapter and execution-manifest identities therefore cannot map a formal-v26 target request to the formal-v24 sequential cache that was created under the predecessor training-provenance digest.

## Preflight Accountability

This defect should have been caught before formal execution. The v26 completed-side dry walk enumerated the 577 existing predecessor entries and proved that each source entry could be mechanically rebound; it did not generate the actual candidate requests that the successor learning algorithm would issue and prove target-request-to-source-key coverage. The ten inherited one-shot entries passed because their candidate identity was already present in the source cache. The first newly frozen inner candidate exposed the unreachable sequential key.

A future successor must add an all-fold, zero-economic target-request dry walk that freezes the same candidate identity inputs as formal execution and proves every completed-side target key resolves to exactly one immutable source key before any nested run begins. Duplicating a source census is insufficient.

## Successor Boundary

Formal-v26 is closed and another execution identity may not start automatically. The safest successor design is to freeze the completed formal-v24 BUY side as an immutable side artifact under its original code and manifest, execute only SELL under separately qualified repaired code, and combine the two side reports through an explicit cross-commit composition contract. An alternative semantic-policy digest would require a new cache-identity contract and exact proof that it excludes training provenance without collapsing distinct compiled policies. Neither route may rewrite formal-v24, strip provenance from historical policy identities, or reinterpret source keys after reading outcomes.

Formal-v26 did not deploy or modify EC2, create a shadow or companion, modify the active owner policy, read Validation or sealed holdout, or grant research, action, or live authority.
