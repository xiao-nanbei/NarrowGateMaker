## Scope

Formal-v21 is an execution-only successor to the stopped formal-v20 run. It preserves the same admitted 30 Development days, 3,516 mechanics opportunities, exact owner B0, eight side-specific duration arms, four-by-three chronological folds, candidate ladder, estimand, statistics, and permissions. It does not read Validation or sealed holdout, modify EC2, create a live observer, or change the active owner policy.

The admitted mechanics panel retains the source SHA of the one-shot runner that created it. Formal-v21 treats that SHA as historical mechanics provenance and rebinds only the source SHA to the clean tagged executor when the canonical module, symbol, role census, queue identity, and clock semantics are unchanged. Any API or semantic drift remains fail-closed; the mechanics rows and opportunity denominator are not rewritten.

## Engine Boundary

The C++ engine is authorized only for outer-train one-shot duration labels. Outer-test and other sequential repeated-policy economics remain Python-authoritative. A one-shot arm remains an independent complete event path; v21 does not claim a single-pass multi-arm economic kernel. All arm paths share one immutable C++ observation tape and the admitted read-only day-input mmap, while each arm owns an independent cooldown state machine.

## Qualification

Before formal economics may start, the first admitted real UTC day must run every admitted opportunity and all eight legal side-specific duration arms through both the existing Python shared-prefix authority and the C++ direct replay. Lockstep hashes a frozen common full-path projection covering duration treatment and exact-owner continuation identity, every fill, every repeated-policy decision, campaign accounting, terminal or censor state, inventory risk, pending lifecycle state, and summary PnL; engine-private duplicate diagnostics are excluded rather than coerced into a false common schema. The receipt must bind the clean commit, annotated tag, execution manifest, source manifest, panel manifest, owner policy, predicate bundle, C++ extension, observation tape, source files, and lockstep digest implementation; it must record zero mismatches and persist no economic values.

## Scheduling

One persistent ten-thread pool owns all C++ arm work. There are no Python day-parent, supervisor, POSIX fork, or nested worker pools. A day opens its BBO, L2, trades, model overlay, and derived arrays once from the content-addressed read-only mmap and builds its compact observation tape once; the pool drains all arm tasks for that day before the next day is opened, bounding resident memory while retaining ten active event loops.

## Fail-Closed Rules

Missing or malformed qualification receipts, policy or source hash drift, a nonzero parity mismatch, an unavailable C++ extension, an invalid observation tape, nested execution, unknown action vocabulary, or a Python sequential-engine substitution rejects the run. Partial v17-v20 strategy-dependent caches are not reusable. Complete candidate-independent day-input mmap bundles remain reusable only after their existing content receipts revalidate.

## Permission

This identity grants no candidate, action, live, Validation, sealed-holdout, or EC2 authority. Passing lockstep authorizes only the frozen formal-v21 offline run; its economic and statistical gates remain unchanged.
